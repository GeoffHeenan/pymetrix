# Validation

Every number pymetrix produces should be checkable against something other than pymetrix. This
page lists what each area is checked against in the test suite, and how closely they agree. The
checks run on every change, on Windows, macOS and Linux.

**Kinds of reference.**

- **Library (wrapped):** pymetrix calls this library to do the work, and the test calls it
  directly. This checks the wrapper: data alignment, sample, degrees of freedom and naming.
- **Library (independent):** pymetrix computes the result itself, and the test compares it with
  another library's result.
- **Other package:** another program's recorded output (named, with its version).
- **Published:** a table or result from a paper.
- **Formula:** a closed form, a hand calculation or a known exact value.
- **Recovery:** a simulation from known true values, which the estimate must recover.

"Default" tolerance means NumPy's `allclose`: relative 1e-5, absolute 1e-8.

How pymetrix defines each statistic (AIC, BIC and HQ as totals, R² variants, degrees of freedom, covariance estimators)
is in [design/definitions.md](design/definitions.md); the reference conformance suite in `tests/reference/`
checks key estimators against certified and published values.

The tables below have about 290 rows for the core and 75 for the finance plugin, most of them several checks of one
method; counting parametrised cases separately, there are several hundred assertions. In the core, the references are
independent libraries, other packages' recorded output (Dynare 6.0, R, gretl, JMulTi, Stata, x13as,
rjd3tramoseats), published tables, closed forms, simulation and recovery; about 20 rows are wrapper checks. In the finance plugin, the copulas are checked against R's VineCopula and copula packages, and options,
volatility and credit against QuantLib, arch, statsmodels and scipy; the rest against closed forms, published
examples (He and Litterman 1999), hand calculations and recovery from simulation.

Apart from these, two checks keep code and app in step. The script the app writes for each demo project,
run in a fresh Python process with no display, reproduces the project's numbers to 1e-8 and loads no Qt
or plotting library. The code in [building and estimating models](modelling-quickstart.md) runs as written.

## Reference conformance suite

`tests/reference/` checks key estimators against certified or published numbers from outside pymetrix. Each case
runs twice: through the public API, and as a recorded call saved to JSON and replayed in a fresh session (see
[design/commands.md](design/commands.md)). The fixtures and their sources are built by
`tests/fixtures/reference/make_reference.py`, from the copies that statsmodels (BSD-3) ships.

| Estimator | Reference | Achieved |
| --- | --- | --- |
| OLS | NIST StRD Longley, certified values | coefficients 10.8 correct digits (LRE), standard errors 8.3, SSR 12.1, R² 14.5; required: 9 and 8 |
| OLS | Stata on Longley: log likelihood, AIC, BIC, White (HC1) errors | as printed (HC1 within 3e-8 relatively) |
| ARMA(1,1), ARMA(2,2) with a constant | gretl, exact maximum likelihood | coefficients 1e-5, log likelihood 1e-6, s.e. 1e-3 (gretl's numerical Hessian) |
| VAR(4) with a constant | JMulTi on statsmodels' macrodata | every coefficient and s.e. to JMulTi's three printed decimals |

The other NIST linear regression sets (Norris, Pontius, NoInt1/2, Filip, Wampler1–5) are added when their files
can be fetched from NIST.

The finance tutorial ([finance-tutorial.md](../packages/pymetrix-finance/docs/tutorial.md)) runs as written on the example datasets. The
Fama-French returns are downloaded on first use, so the tests run it on a simulated stand-in served in the data
library's own file layout (no network); with `PYMETRIX_FRENCH` set to a downloaded `french.parquet`, its claims about
the real data are tested too: momentum's Sharpe ratio and skew, the GRS rejection, minimum variance beating maximum
Sharpe out of sample, and the VaR backtest comparison (checked on the library's September 2026 release). The download
itself (`tests/test_finance_french_download.py`): the dataset built from the five files equals the stand-in's
simulated returns over 100 exactly, the first load fetches once and caches, later loads fetch nothing, and offline the
first load fails with a message that names the library and the cache folder.

## Not yet independently checked

These are native code whose tests check behaviour (direction, consistency, recovery) but not a
number against an outside reference. They are good first tasks for anyone validating against
another package.

- **Equation tests:** Sargan, Durbin-Wu-Hausman and Hansen J for native estimators; McLeod-Li;
  multi-restriction Wald.
- **Forecasts:** dynamic forecasts of an OLS equation with a lagged dependent variable; native
  GJR-GARCH-t forecasts.
- **VARs:** bootstrap impulse-response bands.
- **Bayesian VARs:** sum-of-coefficients and initial-observation priors; hyperparameter
  optimisation; posterior bands; forecasts.
- **State space:** models with priors (posterior mode); forecasts and simulation.
- **Bayesian estimation of models:** the Metropolis-Hastings comparison with Dynare's fs2000 posterior runs only on request (`PYMETRIX_SLOW=1`, about five minutes); last run: every posterior mean within 0.08 posterior standard deviations of Dynare's, standard deviations within 7%, modified harmonic mean 1299.19 against Dynare's 1299.17.
- **Systems:** iterated 3SLS, restricted SUR, nonlinear SUR, the diagonal-covariance test.
- **Dynamic panels:** two-step Windmeijer s.e. (Monte Carlo only); AR(1) and AR(2) tests; Hansen
  J; system GMM.
- **ARDL:** the bounds test (statsmodels computes it; only its verdicts are tested); order
  selection.
- **Panel unit roots and cointegration:** Hadri with a long-run variance; Breitung, Pedroni, Kao and Westerlund against
  another package's output (Stata's `xtunitroot breitung` and `xtcointtest`, or EViews), none of which is at hand.
- **MIDAS:** parametric estimates and nowcasts, against another MIDAS implementation.
- **Disaggregation:** Chow-Lin by maximum likelihood, Fernández, Litterman and additive Denton, against
  another package, for example R's `tempdisagg` (the checks are against formulas written in the tests); the
  reconciliation against another package's (R's `tsbalancing`, or Di Fonzo and Marini's own examples).
- **Model solving:** Dynare's and IRIS's own output for imported models.
- **Seasonal adjustment:** X-13 on Windows and macOS builds of the program (checked here against x13binary's Linux
  build of 1.1 Build 61). TRAMO-SEATS on macOS's Java, which only the weekly full run reaches.
- **Finance** (checked by formulas, hand calculation or simulation, but not against another package): the event-study
  test statistics (their size only; R's estudy2 would be a reference); SVI calibration; the KMV iteration; the copula
  estimates of the Gaussian and t, the BB1 and BB7 estimates and the goodness-of-fit p-values (the densities, CDFs and
  Archimedean fits are checked against statsmodels and R's copula and VineCopula); the McNeil-Frey shortfall test; the dynamic
  Nelson-Siegel estimates (its likelihood is checked).
